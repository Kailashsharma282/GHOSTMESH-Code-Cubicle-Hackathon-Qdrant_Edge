## 3. Strict Real vs. Simulated Architecture Disclosures

In strict adherence to Code Cubicle 6.0 and Qdrant Edge track anti-hallucination rules:

### REAL & PRODUCTION IMPLEMENTED:
1. **Qdrant Edge Shards:** True isolated on-disk vector databases using `QdrantClient(path=...)`. No shared memory between nodes.
2. **Local Vector Search:** Queries run directly against local shards using 384-dimensional dense vectors generated by FastEmbed. Zero cloud dependencies when offline.
3. **Local Egress Queue:** True persistent SQLite database per node with atomic `INSERT`, status flags (`PENDING`, `SYNCED`, `QUARANTINED`), and retry logic.
4. **Qdrant Server Tier:** Full remote Qdrant collection handling global cross-device memories.
5. **Reconciliation Engine:** Deterministic, explainable multi-factor scoring (Cosine similarity, Temporal decay, Confidence weighting, Spatial contradiction rules).
6. **Provenance Lineage:** Directed Acyclic Graph (DAG) recording source devices, timestamps, and cosine scores for synthesized canonical memories.
7. **Privacy Policy Quarantine:** Pre-sync filter evaluating observation content against sensitive data rules (passwords, PINs, IDs, personal records). Physically prevents quarantined items from egressing to the cloud collection.
8. **WebSocket Broadcast:** Genuine event bus publishing real system events (`memory.stored_local`, `sync.queued`, `device.disconnected`, `conflict.detected`, `reconciliation.completed`).

### SIMULATED / EMULATED:
1. **3 Physical Edge Devices:** Emulated as 3 isolated logical edge nodes (Device A - Phone, Device B - Laptop, Device C - Camera) running on independent on-disk directories and ports.
2. **Network Severing:** Simulated via software state toggles (`ONLINE` / `OFFLINE`) that actively halt cloud sync and force all operations to fallback onto local Qdrant Edge storage.

## 5. Bugs Found & Fixed During Hardening

1. **React Rules of Hooks Violation in `DeviceDetailModal.tsx` & `NewMemoryModal.tsx`:**
   - *Issue:* `useState` hooks were declared after early `if (!device) return null;` guard clauses, triggering runtime crashes when switching devices.
   - *Fix:* Re-ordered all hooks to the top of the functional components prior to any conditional returns.
2. **Render Blueprint Plan & Billing Trigger:**
   - *Issue:* `render.yaml` was configured with `plan: starter` and persistent disk, triggering an unexpected credit card payment prompt on free Render accounts.
   - *Fix:* Downgraded configuration to `plan: free` and added SQLite fallback with comprehensive deployment documentation.
3. **Root `.gitignore` Secrets Leak Prevention:**
   - *Issue:* No root `.gitignore` existed, risking accidental commit of local Qdrant lock files and `.env` credentials.
   - *Fix:* Created comprehensive `.gitignore` excluding `data/`, `node_modules/`, `dist/`, `.env`, and video caches.
4. **Embedded Qdrant File Lock Contention in Health Checks:**
   - *Issue:* Standalone audit scripts attempted to initialize a second `QdrantClient(path=...)` against active storage directories, causing `portalocker.exceptions.LockException`.
   - *Fix:* Updated audit scripts to query live backend REST endpoints rather than creating conflicting direct locks.

## 6. Known Limitations

- **Physical Radio Transceivers:** The demo runs on a single host machine with 3 logical process directories. True BLE/LoRa/Wi-Fi mesh propagation delays are simulated via async timers.
- **Hardware Acceleration:** ONNX Runtime runs on CPU execution provider. Search latencies average ~8-14ms per local vector query.
